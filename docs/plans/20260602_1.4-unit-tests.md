# Test-first unit tests for lib + contract helpers

> Lane: TEST. Owns `**/*.test.ts` (unit). Runs in parallel with 1.3 (red→green): tests are written
> against the frozen contracts/signatures, then 1.3 makes them pass.

## Context
Lock the behavior of the pure server utilities before any feature lane builds on them (rule 12, TDD).

**Required reading:** [`CLAUDE.md`](../../CLAUDE.md) · [`architecture.md`](../architecture.md) §2 ·
[`task-breakdown.md`](../task-breakdown.md) #1.4 · the 1.3 plan for exact signatures.

## Goal & non-goals
- **Goal:** Unit tests for password hash/verify, slug + name-normalization, jose sign/verify (incl.
  expired/tampered), reaction-toggle logic, HEIC detection.
- **Non-goals:** No integration tests (those live in Phase 2+), no DB or MinIO round-trips here.

## Files I own
- `src/server/lib/password.test.ts` — hash differs from input; verify true/false; cost applied.
- `src/server/lib/slug.test.ts` — slugify ASCII; non-ASCII/empty → random fallback; `uniqueSlug`
  retries when `existsFn` true; `normalizeName` trims + lowercases (incl. mixed case + spaces).
- `src/server/auth/session.test.ts` — sign→verify round-trip; tampered token rejected; expired token
  rejected; wrong-secret rejected.
- `src/server/lib/heic.test.ts` — `isHeic` true for heic content-type/filename, false for jpeg/png.
- `src/server/domain/reaction-toggle.test.ts` *(pure helper only — if toggle logic is extracted as a
  pure function in 1.3/5.1; otherwise this lands in 5.3)*: same emoji → remove, different → replace,
  none → add.

## Approach
1. Import only the frozen signatures from 1.2/1.3; no mock of internal structure.
2. Use Vitest `unit` project (no DB). Keep each test small and behavioral.
3. Where a real HEIC byte sample is needed for detection, use a tiny fixture or content-type only.

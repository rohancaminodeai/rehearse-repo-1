# Vitest config + test setup/helpers

> Lane: INFRA. Sequential foundation. Establishes the TDD harness all `*.test.ts` files depend on.

## Context
Test-first is mandatory for `src/server/*` + API routes (rule 12); this provides the runner and the
DB/bucket-reset plumbing the integration suites rely on.

**Required reading:** [`CLAUDE.md`](../../CLAUDE.md) · [`task-breakdown.md`](../task-breakdown.md) #0.3 ·
[`mvp-decisions.md`](../mvp-decisions.md) §process.

## Goal & non-goals
- **Goal:** `vitest.config.ts` with a **unit** project and an **integration** project; `test/setup.ts`
  (migrate test DB, truncate tables + empty test bucket between tests); `test/helpers.ts` (request
  helper, auth/session helpers, factory helpers).
- **Non-goals:** No Playwright/E2E (deferred per ADR). No tests yet (those come per-phase).

## Files I own
- `vitest.config.ts`, `test/setup.ts`, `test/helpers.ts`; add `"test"` / `"test:unit"` scripts to
  `package.json` (coordinate — frozen file; do it here in Phase 0 before the freeze).

## Approach
1. Two Vitest projects: `unit` (no DB, fast) and `integration` (uses test containers + setup).
2. `setup.ts`: point Prisma at the test `DATABASE_URL`; run migrations once; `beforeEach` truncate all
   tables and empty the test MinIO bucket for isolation.
3. `helpers.ts`: a `fetchRoute`/handler-invoke helper, a `makeTrainer`/`makeCustomer` factory, and a
   cookie/session builder that uses the real `signSession` (from 1.3) — keep imports lazy to avoid
   pulling Prisma into the unit project.

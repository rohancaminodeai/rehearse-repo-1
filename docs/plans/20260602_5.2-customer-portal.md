## Goal & non-goals
- **Goal:** read-only entries list (preview/download via proxy), trainer comment shown, **emoji
  reaction picker** (PUT upsert, reflects toggle/replace); trainer view surfaces the chosen reaction.
- **Non-goals:** No customer list/other customers, no upload/edit/delete (read-only), no thread.

## Files I own
- `src/app/portal/[slug]/dashboard/page.tsx` — customer-session-scoped entries; same visual language.
- `src/components/reaction-picker/**` — small emoji set (frozen allowlist); calls `PUT .../reaction`.
- `src/components/customer-portal/**` — read-only entry card + preview Dialog + download.
- Reaction **badge** addition in `src/components/inbody-module.tsx` (trainer sees the reaction).

## Approach
0. **Slug↔trainer binding (carried over from the Phase-2 review, rule 5).** The Edge middleware only
   checks that a valid `customer_session` exists — it cannot do the slug→trainerId DB lookup. So this
   page MUST call `getCustomerSession()` and verify `session.trainerId` owns the URL `[slug]`
   (`prisma.trainer.findUnique({ where: { slug } })` → compare ids); on mismatch/missing, redirect to
   `/portal/[slug]/login`. Without this, a customer of trainer A could open trainer B's portal URL.
1. Page reads the customer's own entries only (server-side, via session). Images via the proxy route.
2. Reaction picker: clicking the active emoji toggles off; another replaces. `router.refresh()` after.
3. **Empty state**: no entries yet → friendly message (rule 16). Error + pending states on actions.
4. Trainer-side badge: render `entry.reaction?.emoji` if present in the trainer module (small, serial edit).

# Auth pages: trainer signup/login + customer portal login

> Lane: FE. Owns `src/app/(trainer)/{login,signup}/page.tsx`,
> `src/app/portal/[slug]/login/page.tsx`, `src/components/auth/**`.
> Parallel with 2.1 (BE) and 2.3 (TEST) — codes against the frozen Zod/TS contracts.

## Context
Give trainers and customers the screens to authenticate. Advances FR-1…FR-3, C1.

**Required reading:** [`CLAUDE.md`](../../CLAUDE.md) · [`requirements.md`](../requirements.md) §auth ·
[`task-breakdown.md`](../task-breakdown.md) #2.2 · the mockup visual language (navy/emerald).

## Goal & non-goals
- **Goal:** signup + login forms (trainer), portal login (customer, slug from route); client-side Zod
  validation against frozen schemas; redirect on success; inline error + loading states.
- **Non-goals:** No dashboard (Phase 3), no customer self-signup, no "forgot password".

## Files I own
- `src/app/(trainer)/signup/page.tsx` — email/password/name; POST `/api/auth/trainer/signup`.
- `src/app/(trainer)/login/page.tsx` — email/password; POST `/api/auth/trainer/login`; link to signup.
- `src/app/portal/[slug]/login/page.tsx` — name/password; POST `/api/auth/customer/login` (slug from
  `params`). Minimal branding; no customer list (privacy).
- `src/components/auth/**` — shared `AuthCard`, form field, submit-with-pending helpers (shadcn).

## Approach
1. Reuse the frozen request schemas from `_schemas/auth.ts` for client validation; show `ApiError.message`
   inline on non-2xx. Generic copy on failed login (don't reveal which field).
2. On success redirect: trainer → `/dashboard`, customer → `/portal/[slug]/dashboard`.
3. shadcn `Card`/`Input`/`Button`; emerald primary; **error state + pending state** required (rule 16).

## Goal & non-goals
- **Goal:** `docker-compose.yml` (Postgres + MinIO + a one-shot `mc` bucket-init);
  `docker-compose.test.yml` (postgres-test + minio-test on separate ports/DB); `.env.example` +
  `.env.test.example` (names only, **mirroring compose exactly**); `src/server/lib/env.ts` (Zod,
  fail-fast at startup).
- **Non-goals:** No production deploy config, no secrets committed, no extra services.

## Files I own
- `docker-compose.yml`, `docker-compose.test.yml`, `.env.example`, `.env.test.example`,
  `src/server/lib/env.ts`.

## Approach
1. **Postgres** service with DB/user/password; **MinIO** with root user/password + console :9001,
   API :9000; an `mc` one-shot container that creates the bucket on boot (best-effort; `ensureBucket`
   in 1.3 backstops it).
2. **Test compose** mirrors but on distinct ports + a separate DB/bucket so unit/integration runs never
   touch dev data.
3. **`.env.example` mirrors `docker-compose.yml` exactly** (rule 15): same creds/ports, MinIO keys,
   bucket name, `DATABASE_URL`, `JWT_SECRET` (name only), `S3_ENDPOINT=http://localhost:9000`,
   `S3_FORCE_PATH_STYLE=true`.
4. **`env.ts`**: Zod schema for all required vars; parse at module load; throw (fail-fast) if any
   missing/invalid — the app refuses to boot (rule 14). No `any`.

# Reaction API (customer emoji upsert)

> Lane: BE. Owns `src/app/api/inbody/[id]/reaction/route.ts`, `src/server/domain/reactions.ts`.
> Parallel with 5.2 (FE) and 5.3 (TEST).

## Context
Let a customer react to the trainer's comment with one emoji. Advances FR-15, C4.

**Required reading:** [`CLAUDE.md`](../../CLAUDE.md) · [`requirements.md`](../requirements.md) §reaction ·
[`task-breakdown.md`](../task-breakdown.md) #5.1.

## Goal & non-goals
- **Goal:** `PUT /api/inbody/[id]/reaction` upsert — **customer-only**, must own the entry; same emoji
  toggles off, different replaces; one reaction per entry.
- **Non-goals:** No trainer reactions, no multiple/threaded reactions, no comment thread.

## Files I own
- `src/app/api/inbody/[id]/reaction/route.ts` — `PUT` (set/toggle); maybe `DELETE` (explicit clear).
- `src/server/domain/reactions.ts` — `setReaction(customerId, entryId, emoji)` upsert logic.

## Approach
1. Require a **customer** session; verify the entry's `customerId` equals the cookie's `customerId`
   (rule 4) → else 404.
2. Emoji validated against the frozen allowlist (`_schemas/reaction.ts`). 
3. Upsert by `inbodyEntryId` (unique): no row → create; same emoji → delete (toggle off); different →
   update. Return the resulting `ReactionDTO | null`.

## Summary
- **What changed:** Added `domain/reactions.ts` (`setReaction(customerId, entryId, emoji) → ReactionDTO|null`)
  + thin handler `PUT /api/inbody/[id]/reaction`.
- **Customer-only (rules 4/5):** handler requires `getCustomerSession()`; trainer/no-session → 401. Domain
  loads the entry via `findFirst({ where: { id, customerId } })` so a customer can only react on their OWN
  entry; not-owned/absent → **404** (no existence leak).
- **Toggle model:** reuses the frozen pure `decideReaction(current, incoming)` — add → `reaction.create`;
  different emoji → `reaction.update` (by `inbodyEntryId` @unique); same emoji → `reaction.delete` (returns
  `null`, toggle off). Always ≤1 reaction row per entry.
- **Validation (rule 7):** body checked against the frozen `setReactionSchema` (emoji allowlist) → 400 on
  miss; all errors via `toApiError`. No separate DELETE route (toggle-off covers clearing — rule 2).
- **Verified:** typecheck + lint clean; 5.3 integration green (toggle/replace, access control, stale session).

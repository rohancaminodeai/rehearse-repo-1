# Auth routes + Edge middleware

> Lane: BE. Owns `src/app/api/auth/**`, `src/middleware.ts`, `src/server/domain/auth.ts`.
> Runs in parallel with 2.2 (FE) and 2.3 (TEST) — disjoint paths.

## Context
Stand up the two-role auth slice so every later phase has real sessions to guard. Advances
FR-1…FR-5, C1, and NFR security rules.

**Required reading:** [`CLAUDE.md`](../../CLAUDE.md) · [`requirements.md`](../requirements.md) §auth ·
[`architecture.md`](../architecture.md) §auth-model · [`task-breakdown.md`](../task-breakdown.md) #2.1.

## Goal & non-goals
- **Goal:** trainer signup/login/logout + customer login routes; `src/server/domain/auth.ts` plain
  functions; Edge middleware guarding `/dashboard/**` and `/portal/[slug]/dashboard`.
- **Non-goals:** No groups/customers CRUD (Phase 3), no UI (2.2), no password reset / email verify.

## Files I own
- `src/app/api/auth/trainer/signup/route.ts` — Zod-validate → `domain.signupTrainer` → set
  `trainer_session` cookie. Unique slug from name (random suffix fallback). 409 on dup email.
- `src/app/api/auth/trainer/login/route.ts` — verify creds → set cookie. **Generic** error on failure.
- `src/app/api/auth/logout/route.ts` — clear both cookies (idempotent).
- `src/app/api/auth/customer/login/route.ts` — body `{name, password}`; trainer resolved from slug in
  the request (path or body per contract); normalized-name lookup scoped to that trainer; set
  `customer_session {customerId, trainerId}`. Generic error.
- `src/server/domain/auth.ts` — `signupTrainer`, `loginTrainer`, `loginCustomer(slug, name, password)`;
  pure (no `next/*`), uses lib password/session/slug + prisma.
- `src/middleware.ts` — Edge. jose-verify the right cookie per path; redirect unauthenticated
  `/dashboard/**` → `/login`, `/portal/[slug]/dashboard` → `/portal/[slug]/login`. **No Prisma/bcrypt.**

## Approach
1. Handlers stay thin (rule 3): parse → Zod → domain → set cookie/format. Cookie writes via the
   lib helpers from 1.3.
2. `loginCustomer` normalizes the submitted name (trim+lowercase) and matches `@@unique` row; binds
   cookie to that trainer's id.
3. Middleware matches via `config.matcher`; tampered/expired token → redirect, never 500 (rule 10).

## Summary
- **What changed:** Added the two-role auth slice. `src/server/domain/auth.ts` (pure): `signupTrainer`
  (bcrypt + unique slug via `uniqueSlug`, dup email → `ConflictError`), `loginTrainer` (generic
  `AuthError` for both unknown-email and bad-password), `loginCustomer(slug, name, password)` (trainer
  resolved from slug, customer matched by `@@unique([trainerId, normalizeName(name)])`, generic error —
  valid creds under trainer A can't auth via trainer B's slug). Thin handlers under
  `src/app/api/auth/**` (signup 201, login 200, logout clears both cookies/idempotent, customer login
  200) that parse → safeParse (400 on fail) → domain → `signSession(payload, env.JWT_SECRET)` → set
  cookie → DTO; all errors via `toApiError`. `src/middleware.ts` (Edge, jose-only via
  `@/server/auth/jwt`) guards `/dashboard/:path*` → `/login` and `/portal/:slug/dashboard/:path*` →
  `/portal/<slug>/login`, never throws.
- **Decision:** `customerLoginSchema` is frozen as `{name, password}`, so the customer-login route
  reads the slug from the **query string** (`?slug=`).
- **Verified:** typecheck + lint clean; 18 auth integration tests (2.3) green.

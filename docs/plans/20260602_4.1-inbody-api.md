# InBody API: upload, file proxy, comment, delete

> Lane: BE. Owns `src/app/api/inbody/**` (except `[id]/reaction`), `src/server/domain/inbody.ts`.
> Parallel with 4.2 (FE) and 4.3 (TEST).

## Context
The core feature: trainers attach InBody images (with a comment) to a customer and view them safely.
Advances FR-11…FR-14, T5–T6 and the storage/HEIC/IDOR rules.

**Required reading:** [`CLAUDE.md`](../../CLAUDE.md) · [`requirements.md`](../requirements.md) §inbody ·
[`architecture.md`](../architecture.md) §upload-flow · [`task-breakdown.md`](../task-breakdown.md) #4.1.

## Goal & non-goals
- **Goal:** upload (multipart → HEIC→JPEG → MinIO put → DB row, cleanup on failure); auth-checked file
  stream (`?download=1`); patch comment; delete (DB + MinIO).
- **Non-goals:** No reaction (Phase 5), no metrics extraction, no thumbnails/resize.

## Files I own
- `src/app/api/inbody/route.ts` — `POST` upload (multipart `file` + `customerId` + `comment?`),
  `GET?customerId=` list entries for an owned customer.
- `src/app/api/inbody/[id]/route.ts` — `PATCH` comment, `DELETE` (DB row + MinIO object).
- `src/app/api/inbody/[id]/file/route.ts` — `GET` streams the object; `?download=1` sets
  `Content-Disposition: attachment`. **Auth + ownership checked** (trainer owns, or customer owns).
- `src/server/domain/inbody.ts` — `uploadEntry`, `listEntries`, `patchComment`, `deleteEntry`; plain
  functions using lib s3/heic/prisma; all scoped by ownership.

## Approach
1. **Validate** file server-side: content-type allowlist (jpeg/png/heic) + size cap (~10MB) → 400.
2. If HEIC → `heicToJpeg` (try/catch → 400, never store unconvertible). Generate **UUID objectKey**.
3. **Order**: `putObject` → create DB row; if DB write throws, `deleteObject` (no orphan) and rethrow.
4. **File route** authorizes by session role: trainer must own the entry's customer; customer cookie's
   `customerId` must equal the entry's customer. Mismatch → 404 (no existence leak). IDOR = P0.
5. `deleteEntry`: delete DB row then best-effort `deleteObject`.

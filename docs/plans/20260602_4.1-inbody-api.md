# InBody API: upload, file proxy, comment, delete

> Lane: BE. Owns `src/app/api/inbody/**` (except `[id]/reaction`), `src/server/domain/inbody.ts`.
> Parallel with 4.2 (FE) and 4.3 (TEST).

## Context
The core feature: trainers attach InBody images (with a comment) to a customer and view them safely.
Advances FR-11…FR-14, T5–T6 and the storage/HEIC/IDOR rules.

**Required reading:** [`CLAUDE.md`](../../CLAUDE.md) · [`requirements.md`](../requirements.md) §inbody ·
[`architecture.md`](../architecture.md) §upload-flow · [`task-breakdown.md`](../task-breakdown.md) #4.1.

## Goal & non-goals
- **Goal:** upload (multipart → HEIC→JPEG → MinIO put → DB row, cleanup on failure); auth-checked file
  stream (`?download=1`); patch comment; delete (DB + MinIO).
- **Non-goals:** No reaction (Phase 5), no metrics extraction, no thumbnails/resize.

## Files I own
- `src/app/api/inbody/route.ts` — `POST` upload (multipart `file` + `customerId` + `comment?`),
  `GET?customerId=` list entries for an owned customer.
- `src/app/api/inbody/[id]/route.ts` — `PATCH` comment, `DELETE` (DB row + MinIO object).
- `src/app/api/inbody/[id]/file/route.ts` — `GET` streams the object; `?download=1` sets
  `Content-Disposition: attachment`. **Auth + ownership checked** (trainer owns, or customer owns).
- `src/server/domain/inbody.ts` — `uploadEntry`, `listEntries`, `patchComment`, `deleteEntry`; plain
  functions using lib s3/heic/prisma; all scoped by ownership.

## Approach
1. **Validate** file server-side: content-type allowlist (jpeg/png/heic) + size cap (~10MB) → 400.
2. If HEIC → `heicToJpeg` (try/catch → 400, never store unconvertible). Generate **UUID objectKey**.
3. **Order**: `putObject` → create DB row; if DB write throws, `deleteObject` (no orphan) and rethrow.
4. **File route** authorizes by session role: trainer must own the entry's customer; customer cookie's
   `customerId` must equal the entry's customer. Mismatch → 404 (no existence leak). IDOR = P0.
5. `deleteEntry`: delete DB row then best-effort `deleteObject`.

## Summary
- **What changed:** Added `domain/inbody.ts` (plain functions: `uploadEntry`, `listEntries`,
  `patchComment`, `deleteEntry`, `getEntryForViewer`) + thin handlers `POST/GET /api/inbody`,
  `PATCH/DELETE /api/inbody/[id]`, and the auth-checked proxy `GET /api/inbody/[id]/file`.
- **Upload:** multipart → ownership check → type allowlist (jpeg/png/heic/heif, else 400) → size cap vs
  `env.MAX_UPLOAD_BYTES` (400) → HEIC→JPEG when `isHeic` → **UUID objectKey** (`crypto.randomUUID()` +
  ext, never the raw filename, rule 8) → **putObject FIRST, then DB create; on DB failure best-effort
  `deleteObject` + rethrow** (no orphan object). Returns DTO 201.
- **File proxy (P0 IDOR):** reads both cookies, delegates to `getEntryForViewer` which scopes at the
  query level — trainer: `customer: { trainerId }`; customer: `customerId = session.customerId` (cookie
  bound to one customer, rule 5); no session → 401; any mismatch → **404** (no existence leak). Streams
  via a no-cast `toResponseBody` helper (web stream passes through; Node `Readable` wrapped in a DOM
  `ReadableStream`). `?download=1` → `Content-Disposition: attachment` (filename sanitized).
- **Delete (rule 11):** DB row removed, then best-effort `deleteObject` (MinIO failure never fails the
  request). DTOs never leak `objectKey`.
- **Frozen-file fix (surfaced bug):** `src/server/lib/heic.ts` passed a raw `ArrayBuffer` to
  `heic-convert`, which crashes at runtime (`heic-decode` spreads `.slice()` — Node ≥ requires an
  iterable typed array). Fixed to pass a `Uint8Array`; the inaccurate `@types/heic-convert`
  (`buffer: ArrayBufferLike`) is corrected by a local `src/types/heic-convert.d.ts` (no `any`/cast,
  rule 9). Verified end-to-end with a real `test/fixtures/sample.heic` → valid JPEG (`ff d8 ff`).
- **Verified:** typecheck + lint clean; 4.3 integration suite green (file IDOR, HEIC→JPEG, no-orphan
  cleanup, delete-removes-object, comment edit).

## Goal & non-goals
- **Goal:** group create/list; customer create/patch/delete — all scoped to the session trainer with
  ownership checks; password set/reset on customer; name normalization + per-trainer uniqueness.
- **Non-goals:** No InBody entries (Phase 4), no pagination, no group delete UI niceties beyond cascade.

## Files I own
- `src/app/api/groups/route.ts` — `GET` (trainer's groups + customers for sidebar), `POST` (create).
- `src/app/api/customers/route.ts` — `POST` (create: requires `groupId`, name, password).
- `src/app/api/customers/[id]/route.ts` — `PATCH` (rename / move group / reset password),
  `DELETE` (cascade; **MinIO object cleanup** for the customer's entries — rule 11, best-effort).
- `src/server/domain/groups.ts`, `src/server/domain/customers.ts` — plain functions; all queries
  scoped by `trainerId`; throw typed errors mapped to 400/403/404/409.

## Approach
1. Every read/write filters by the session `trainerId` (rule 4). A customer/group not owned → 404 (don't
   leak existence).
2. **Customer requires a group** (reject if `groupId` missing or not owned). Hash the access password.
3. Name normalization on create + patch; **`@@unique([trainerId, nameNormalized])`** violation → 409.
4. `DELETE` customer: collect entry objectKeys → Prisma delete (cascade) → best-effort `deleteObject`
   for each key (don't fail the request if MinIO delete fails; log).

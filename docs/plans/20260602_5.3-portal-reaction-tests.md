## Approach — cases
1. **Upsert**: no reaction → PUT creates; **same emoji again → removed** (toggle); **different emoji →
   replaced** (still exactly one row).
2. **Idempotency**: repeated identical PUTs converge to a stable state.
3. **Access control**: customer A cannot react on B's entry (→404); a trainer session cannot react
   (customer-only); wrong-trainer customer cookie rejected.
4. **Stale session**: customer deleted mid-session → reaction/portal request → 401/redirect (not 500).
5. **Reflected to trainer**: after a reaction, the entry DTO the trainer reads includes it.

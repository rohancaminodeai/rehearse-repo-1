## Approach — cases
1. **Groups**: create + list returns only the session trainer's groups; trainer A cannot read B's.
2. **Customers create**: requires owned `groupId` (missing/unowned → 400/404); password hashed.
3. **Name uniqueness**: duplicate normalized name under the same trainer → 409; same name under a

4. **IDOR**: trainer A `PATCH`/`DELETE` on B's customer → 404 (no existence leak).
5. **Delete cascade**: deleting a customer removes its entries (DB) and **calls MinIO delete** for each
   objectKey (assert via a stubbed/recording s3 or a real test bucket count).
6. **Patch**: rename, move group, reset password each persist.
